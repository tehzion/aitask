## 2. Recipients

- **Resolver:** `resolveTaskUpdateRecipientIds` — Boss Koo (oversight) + owning PM (`assignedBy` → `createdBy` → client owner → project owner) + task contact (if they can still view the task). Recipients collected in a `Set`, so **no duplicates**.
- **Actor exclusion:** `taskUpdateNotifications(..., excludeUserId)` drops the acting user from their own action feed.
- **Department boundary:** HOD/Staff recipients are gated by `canViewTask`/`isMemberInDepartment`; task contact only added when `canViewTask(contact, ...)`.
- **One-audience invariant:** `makeNotification` rejects any draft with `targetUserId + targetRole + targetClient !== 1` (prevents blank/multi-target rows and matches the DB invariant).
