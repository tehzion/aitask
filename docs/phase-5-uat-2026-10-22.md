## Findings under investigation

### P1 — Super Admin onboarding request contract is incompatible with v3 journal

The actual Edge handler failed the native recovery test with HTTP 409. Code review
found it always included `projectIds` in the Super Admin reservation/finalization
payload, but the existing `aitask_reserve_member_onboarding` SQL deliberately
rejects unknown payload keys. The PM-only assignment array belongs in the separate
`aitask_pm_upsert_project_member` call. The smallest repair removes that array from
the v3 journal payload while preserving the scoped PM call and all SQL validation.
No schema or permission change is needed. Real-handler retest remains required.

### QA fixture drift — explicit project membership

The native Staff/HOD/PM save probe originally failed PM completion with generic
`VALIDATION`. Temporary diagnostics applied only to a disposable database exposed
the underlying rejection: “This company is outside your portfolio.” Its project
had no PM assignment. Correcting the fixture's explicit PM/HOD/Staff membership
allowed the complete native save probe to pass without changing product access.
The temporary database diagnostic mutation was removed before retesting.

The HOD status fixture also omitted explicit HOD membership. Its failure occurred
before a write, at the local action guard. The fixture now declares intended
project members. Retest pending. Neither denial is classified as a product access
defect without a failing correctly assigned case.

One disposable-stack start failed before scenarios ran. The rollout runner now
retains only sanitized failure lines from CLI stdout, rather than hiding all
startup diagnostics or printing local service credentials. Root cause of that
isolated startup failure is not established.

### Production security advisories

Fresh read-only advisor results: 9 INFO policy-less RLS tables, 19 WARN
authenticated SECURITY DEFINER RPC signatures, and leaked-password protection
disabled (WARN). The first two categories include intentionally denied direct
tables and scoped command APIs; do not “fix” them by granting table access or
removing required authorization behavior. Local SQL/RPC negative tests and function
boundary review are required evidence. Leaked-password protection remains an
external Auth configuration risk; no production configuration or paid plan change
has been made.
