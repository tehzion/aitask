# AiTask Platform Development Backlog

Backlog created: 2026-10-18 (MYT)  
Source: `AITASK_PLATFORM_FEATURE_AUDIT.md`  
Scope: Phase 4–7 operations and platform enhancements

## Prioritisation rules

- **P0 — Critical correction:** release/security truth, data isolation, or a current regression that invalidates the verification gate.
- **P1 — High-value improvement:** directly reduces operational manual work or closes a major role/client workflow gap.
- **P2 — Useful enhancement:** improves visibility or efficiency after the core model is stable.
- **P3 — Future consideration:** requires new commercial data, broader policy decisions, or disproportionate complexity.

Effort is a delivery estimate for one experienced engineer familiar with this repository, excluding external approvals, production deployment windows, and user research.

## Cross-cutting UX, i18n, and reliability requirements

Every P1/P2 feature must:

- use existing layout, modal, loading, error, confirmation, and empty-state components where possible;
- add English and Simplified Chinese copy and pass `pnpm verify:i18n`;
- preserve mobile usability with a non-Gantt alternative for timelines;
- deep-link to existing records rather than duplicating task/project/client workflows;
- create server-side authorization and negative tests before exposing new data;
- preserve onboarding/tutorial behavior and avoid overlays that block unrelated navigation;
- use idempotency keys and audit entries for background generation and notifications;
- update the enhancement report with executed checks only.
